# System A — UniPath Research Agent Architecture & Pipeline Specification

**Document Version:** 1.0
**Target Audience:** System Architects & AI Engineers

---

## 1. System Overview

The UniPath Research Agent (System A) is a private, administrative AI engine designed to automate the discovery, structured extraction, claim-level evidence linking, and deterministic validation of university and scholarship information.

```
+-----------------------------------------------------------------------------------+
|                            ADMINISTRATIVE CONSOLE                                 |
|  "Research Moroccan engineering schools (ENSIAS, EMI, EHTP) CS programs..."        |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                         STAGE 1: INSTRUCTION PARSER                                |
|  - Translates natural language into structured task schema                         |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                         STAGE 2: SOURCE DISCOVERY                                 |
|  - Queries registered official portals (ensias.um5.ac.ma, emi.ac.ma, um6p.ma)    |
|  - Assesses robots.txt, terms of use, and access constraints                      |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                         STAGE 3: EVIDENCE COLLECTION                              |
|  - Extracts text blocks, admission guidelines, and deadline schedules             |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                     STAGE 4: CLAIM-LEVEL EVIDENCE LINKING                         |
|  - Links fields (e.g., application_deadline) to exact source URLs and quotes      |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                     STAGE 5: DETERMINISTIC VALIDATION                             |
|  - Checks for duplicate institutions, broken URLs, expired academic cycles         |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                 STAGE 6: REVIEW QUEUE STAGING (UNPUBLISHED)                      |
|  - Staged as ProposedRecord with review_status = 'pending_review'                 |
|  - Human admin approval required before publishing                                |
+-----------------------------------------------------------------------------------+
```

## 2. Claim-Level Evidence Data Model

To ensure absolute trust and transparency, every proposed record attaches `ClaimEvidence` objects to individual fields:

```typescript
export interface ClaimEvidence {
  id: string;
  proposedRecordId?: string;
  entityType: 'university' | 'program' | 'scholarship';
  fieldName: string; // e.g. 'application_deadline'
  claimValue: string; // e.g. '2025-06-30'
  sourceUrl: string; // e.g. 'http://ensias.um5.ac.ma/admissions/concours'
  sourceTitle: string;
  sourceType: 'official_website' | 'government_portal' | 'admissions_portal' | 'third_party';
  evidenceExcerpt: string; // Direct quote from page
  academicCycle: string; // e.g. '2025/2026'
  verificationStatus: 'VERIFIED' | 'UNVERIFIED' | 'OUTDATED';
  verifiedAt: string;
}
```

---

## 3. Human Approval Gate & Audit History

No proposed university, academic program, or scholarship record generated by System A is published automatically to the public dataset. An administrator must explicitly review the claim-level evidence cards, inspect data diffs, and click **Approve & Publish**.
